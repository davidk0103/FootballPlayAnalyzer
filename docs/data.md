## Source

- [nflverse-data](https://github.com/nflverse/nflverse-data) release `pbp`,
  file `play_by_play_<season>.parquet`. Seasons 2023 and 2024 in M1.
- Version marker: the release's `timestamp.json` plus each file's SHA-256.
- Players: release `players`, file `players.parquet`, keyed on `gsis_id`.
- Field definitions: the nflreadr data dictionary (`dictionary_pbp.csv`, 372 fields).

## Columns used

- IDs and context: `game_id`, `play_id`, `season`, `season_type`, `week`,
  `game_date`, `home_team`, `away_team`, `posteam`, `defteam`.
- Situation: `qtr`, `game_seconds_remaining`, `down`, `ydstogo`, `yardline_100`,
  `score_differential`.
- Outcome: `play_type`, `yards_gained`, `epa`, `success`.
- Players: `passer_player_id`, `rusher_player_id`, `receiver_player_id`.
- Indicators: `touchdown`, `interception`, `fumble_lost`, `complete_pass`, `sack`,
  `pass`, `rush`, `first_down`, `penalty`, `third_down_converted`,
  `two_point_attempt`, `qb_kneel`, `qb_spike`, `aborted_play`, `play_deleted`.

## Known definitions

- `success` is `epa > 0` (nflverse), not the classic 40/60/100% rule.
- `play_type == "pass"` includes sacks; `"run"` includes scrambles.
- `play_type == "no_play"` marks plays wiped out by penalty.
- `yards_gained` excludes yards from fumble recoveries and laterals.
- `play_id` is unique only within a game; natural key is `(game_id, play_id)`.

## Missing values

Nullable source columns are stored as `NULL`. Ingestion never writes 0 for a
missing value, and a metric with a zero denominator returns `null`.

## Verified decisions (from profiling, release of 2026-10-10)

The plan's "still to verify" items, resolved against the real files:

1. **Column presence and null rates.** All required columns exist in both
   seasons (372 columns each). Within pass/run rows, every situation, outcome,
   and indicator column is 0% null except `down` (0.35% in 2023, 0.42% in 2024),
   which is null exactly on two-point attempts. `epa` and `success` are never null
   on pass/run rows; `success` always equals `epa > 0`.
2. **Team abbreviations.** Both seasons use the same 32 abbreviations
   (ARI ... WAS, with `LA` for the Rams, `LAC`, `LV`). No legacy codes
   (OAK, SD, STL) appear in 2023-2024, so M1 needs no abbreviation mapping.
   The `teams` table is seeded from a static list keyed on these codes.
3. **`third_down_converted` and penalties.** It is 1 when a third-down play that
   stood produced a first down, *including* first downs awarded by a defensive
   penalty on a play that stood (42 in 2023, 36 in 2024). It is never 1 on a
   `no_play` row, so first downs from penalties that wiped out the play are not
   counted. 14 (2023) and 10 (2024) pass/run third downs with an accepted
   penalty have neither `third_down_converted` nor `third_down_failed`; PlaybookIQ
   counts them as attempts that did not convert.
4. **`no_play` rows.** 4,555 (2023) and 4,936 (2024). Only about 55% have
   `penalty == 1`; the rest are timeouts, challenges, and similar
   administrative rows. All carry a non-null `epa`, so they must be excluded
   explicitly. They are excluded from every M1 metric (they are not stored as
   scrimmage plays; see below).
5. **Players.** The `players` release has 24,853 rows keyed on a unique, never-null
   `gsis_id`, with `display_name`, `position`, and `position_group`. 100% of the
   passer/rusher/receiver IDs in both seasons are found there.

Further findings that shape the schema and metric definitions:

- `qb_kneel` and `qb_spike` are their own `play_type` values, so filtering
  `play_type in ('pass', 'run')` already drops them.
- Sacks are always `play_type == 'pass'`; scrambles are always `'run'`.
- Two-point attempts (126 / 148) are `pass`/`run` rows with null `down`; they are
  excluded from scrimmage metrics via `two_point_attempt`.
- `aborted_play` (96 / 114 within pass/run) are real offensive snaps with EPA
  (botched snaps); they stay in.
- `play_deleted` is 0 in both seasons; still honored if it appears.
- A team offense runs about 1,050 regular-season scrimmage plays per season
  (range 977-1,167).
- `(game_id, play_id)` has no duplicates in either file.

### Scrimmage play definition (used by all M1 metrics)

`play_type in ('pass', 'run')` and `two_point_attempt != 1` and
`play_deleted != 1` and `posteam` not null.

### What ingestion stores

Every row with a non-null `play_type` other than `no_play` is stored in `plays`
(kickoffs, punts, field goals, kneels, spikes, two-point tries included, with
flags), so later milestones can analyze special teams without re-ingesting.
Rows with null `play_type` (quarter/game end markers, timeouts) and `no_play`
rows are counted in the dataset summary but not stored. Rows that fail
validation (for example, missing `game_id`/`play_id`, or a team code not in the
seeded list) go to `rejected_rows` with a reason.
